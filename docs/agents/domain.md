# Domain Docs

## Before exploring

Read root `GLOSSARY.md` and any ADRs in `docs/adr/` relevant to the work.

If these files do not exist, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

## Layout

This repository uses a single-context layout:

- `GLOSSARY.md`: domain terminology.
- `docs/adr/`: architectural decision records.

## Vocabulary

Use terms as defined in the glossary in issues, proposals, hypotheses,
and tests. Reconsider unfamiliar terms; note real vocabulary gaps for
domain-modeling.

## Decision conflicts

If a proposal contradicts an existing ADR, explicitly identify the ADR
and explain why the decision should be reopened.
